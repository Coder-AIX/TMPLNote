# 百度网盘自动备份与双向同步

本文说明 TMPLNote 的百度网盘加密存档、自动加密备份与双向同步：如何配置、如何触发、冲突与删除如何处理、口令与 token 存在哪里，以及常见问题与已知限制。

> 适用范围：当前版本的 `src/lib/baidu`、`src/lib/stores/baiduAuto.js` 与「设置 → 网盘」界面。
> 所有示例中的 `<...>` 均为占位符，请替换为你自己的配置。

## 1. 功能概览

TMPLNote 提供四种与百度网盘相关的能力：

| 能力 | 说明 | 云端文件名 |
| --- | --- | --- |
| 手动加密存档 | 在「设置 → 网盘」手动导出一份完整备份，设置口令加密后上传；可列出、下载、解密、合并或覆盖恢复、删除。 | `tmplnote-archive-YYYYMMDD-HHmmss.tmplenc` |
| 自动加密备份 | 应用在满足条件时自动导出完整备份、用自动同步口令加密并上传；按保留份数轮换旧自动备份。 | `tmplnote-auto-YYYYMMDD-HHmmss-<device8>-<rand4>.tmplenc` |
| 双向同步 | 以云端最新一份自动备份作为远端状态，与本地、上次同步基线做三方合并；新增、修改、删除、移动可传播。 | 同步完成后上传新的自动备份 |
| 冲突副本 | 同一笔记在本地与远端都被修改且内容不同时，保留较新记录，把较旧内容复制为独立笔记，标题带「冲突副本」。 | 包含在同步后上传的自动备份中 |

手动存档与自动备份使用同一套 `.tmplenc` 加密格式，因此手动「下载并恢复」可以解密任意自动备份（需要知道对应口令）。手动存档不会被自动保留策略清理。

## 2. 前置条件

1. **百度网盘账号与应用**
   - 在百度网盘开放平台创建应用，开通上传相关权限。
   - 应用目录必须位于 `/apps/{应用名}`，例如 `/apps/TMPLNote`；同步与备份只能访问该目录。
2. **`access_token`**
   - 通过百度 OAuth 简化模式获取，`scope` 至少包含 `basic,netdisk`。
   - token 约 30 天过期，过期后需要重新获取并粘贴。
3. **桥接服务**
   - 百度网盘 OpenAPI 不返回 CORS 头，下载还要求 `User-Agent: pan.baidu.com`，浏览器无法直连。
   - **Cloudflare Pages**：仓库内 `functions/api/baidu.js` 自动生效，桥接地址使用默认 `/api/baidu`。
   - **GitHub Pages 等纯静态部署**：需要自行部署同逻辑的 Worker，并在设置页填写完整桥接地址。
   - **本地开发**：`npm run dev` 内置 `/api/baidu` 中间件，可直接联调。
4. **自动同步口令**
   - 至少 8 位；用于自动备份/同步的本地加密。
   - 口令遗失后，云端自动备份与手动存档都无法解密。
5. **安全上下文**
   - 加密依赖 WebCrypto，需要通过 HTTPS 或 `localhost` 访问。

## 3. 首次配置

### 3.1 配置百度网盘连接

1. 打开 **设置 → 网盘**。
2. 在 `access_token` 输入框粘贴 token。
3. 填写 **应用目录**，必须与开放平台注册的产品名一致，例如 `/apps/TMPLNote`。
4. 填写 **桥接地址**：
   - Cloudflare Pages / 本地开发：保留 `/api/baidu`；
   - 静态部署：填写你自建 Worker 的完整 HTTP(S) 地址。
5. 点击 **验证并保存**。只有验证成功，token、应用目录与桥接地址才会写入本机设置。
6. 验证成功后可点击 **刷新存档**，确认能列出应用目录下的 `.tmplenc` 文件。

### 3.2 启用自动备份

在 **设置 → 网盘 → 自动同步与备份** 中：

1. 点击 **启用自动备份…**。若尚未完成上一步，按钮不可用并提示先完成连接。
2. 设置 **自动同步口令** 并再次确认；至少 8 位。
3. 选择是否 **在本机加密保存口令**（默认开启）：
   - 开启：口令以本机设备密钥加密后保存，支持无人值守自动备份；
   - 关闭：口令只保留在当前会话，每次打开应用需要手动解锁。
4. 选择 **自动备份周期**：15 / 30 / 60 / 180 / 1440 分钟，默认 **30 分钟**。
5. 选择 **保留份数**：界面预设 3 / 7 / 15 / 30，默认 **7 份**；实际允许 1–100，超出预设的当前值也会保留在选项中。
6. 可选开启 **双向同步（多设备）**。首次开启前请确认云端最新自动备份属于同一份笔记，避免把无关数据合并进来。
7. 点击 **启用**。启用成功后约 5 秒会安排一次首次运行。

### 3.3 立即备份 / 立即同步

- 未开启双向同步时，状态卡按钮为 **立即备份**：强制上传一份新的自动备份。
- 开启双向同步后，按钮为 **立即同步**：执行一次完整的下载、合并、写库、上传流程。
- 手动运行不受「30 秒无输入」与「60 秒最小间隔」限制，但仍要求已配置、已启用、已解锁、在线且没有进行中的任务。

## 4. 自动备份机制

### 4.1 触发条件

自动运行由调度器统一安排，可能来自以下触发：

| 触发 | 延迟 / 间隔 |
| --- | --- |
| 本地笔记或文件夹变化 | 防抖 **90 秒** 后安排 |
| 周期兜底 | 默认 **30 分钟**，可选 15 / 30 / 60 / 180 / 1440 分钟 |
| 应用启动后首次检查 | **15 秒** |
| 网络恢复（`online`） | **3 秒** |
| 页面回到前台（`visibilitychange`） | **3 秒** |
| 启用自动功能成功 | **5 秒** 后首次运行 |

### 4.2 自动运行保护

自动运行必须同时满足以下条件，否则会跳过并安排下一次检查：

- 已完成百度网盘连接配置；
- 自动功能已启用；
- 当前会话已解锁，口令可用；
- 在线；
- 页面可见；
- 访问锁未处于锁定状态；
- 没有进行中的备份或同步（单飞）；
- 最近 **30 秒** 内没有键盘或指针输入；
- 距上次自动运行至少 **60 秒**。

失败后的自动重试还会受到退避限制：token 失效时停止自动尝试，等待用户重新验证；其它错误至少间隔 5 分钟（且不小于当前周期）后再试。手动运行不受退避限制。

### 4.3 数据指纹与跳过

自动备份（未开启双向同步）会在上传前计算本地数据指纹：

- 指纹由有效笔记与文件夹的稳定字段（如 `id`、`updatedAt`、`folderId`、`parentId` 等）经 SHA-256 计算；
- 自动运行发现指纹与上次成功备份一致时直接跳过，不重复上传；
- 手动「立即备份」会强制上传，不受指纹限制；
- 开启双向同步后，由同步引擎判断远端是否变化，不再使用「本地指纹未变就跳过」的预判。

### 4.4 文件命名与保留

自动备份文件名格式：

```text
tmplnote-auto-YYYYMMDD-HHmmss-<device8>-<rand4>.tmplenc
```

- `YYYYMMDD-HHmmss`：本地时间；
- `<device8>`：设备标识前 8 位（仅保留字母数字，无可用字符时为 `local`）；
- `<rand4>`：4 位随机小写十六进制，仅用于避免同名。

保留策略：

- 按云端修改时间倒序，只保留最新的 `keepCount` 份自动备份；
- 刚上传的那一份始终受保护，即使数量超出也不会被删；
- 只处理 `tmplnote-auto-` 前缀的 `.tmplenc`，**手动 `tmplnote-archive-*` 存档永远不会被自动清理**；
- 删除旧备份失败只记录警告，不影响本次备份成功。

### 4.5 恢复自动备份

自动备份与手动存档格式一致。在云端存档列表中选择任意 `tmplnote-auto-*` 文件，点击 **下载并恢复…**，输入该备份使用的口令，即可解密并选择合并或覆盖恢复。

## 5. 双向同步机制

### 5.1 远端状态的来源

云端以 **最新一份自动备份**（`tmplnote-auto-*.tmplenc`，按修改时间倒序取第一份）作为远端状态。同步不会读取或修改手动 `tmplnote-archive-*` 存档。

为判断「谁新增、谁修改、谁删除」，本地设置中保存上次成功同步的基线：

```text
baiduAuto.base = {
  notes:   { <noteId>: <updatedAt> },
  folders: { <folderId>: <updatedAt> }
}
```

基线只保存 `id → updatedAt`，不保存笔记正文，也不包含 token 或口令。

### 5.2 同步流程

一次双向同步按顺序执行：

1. **列出**：读取本地全部笔记与文件夹，计算本地指纹；列出云端自动备份。
2. **判断跳过**：若云端最新文件名与上次处理的一致、本地指纹未变、且存在上次同步时间，则本轮跳过。
3. **下载解密**：取最新自动备份，获取下载链接、下载并解密，得到远端快照。回收站中的笔记不参与合并。
4. **三方合并**：以本地、远端、`base` 进行合并，得到最终笔记/文件夹、应用计划和冲突列表。
5. **单事务写库**：在一个 IndexedDB 读写事务中写入最终文件夹、软删除被远端删除的本地笔记、写入最终笔记、删除被合并掉的文件夹，并修复文件夹引用。
6. **上传合并结果**：把合并后的完整数据加密上传为新的自动备份，并按保留份数清理旧自动备份。
7. **更新基线**：上传成功后写入新的 `base`、`lastSyncAt`、`lastRemoteName`、`lastFingerprint` 等。任何一步失败都不会更新成功时间与基线。

### 5.3 变更传播

- **新增**：本地或远端新增的记录会进入合并结果。
- **修改**：单侧修改采用修改侧内容。
- **删除**：单侧删除且另一侧未修改时，删除会传播。
- **移动**：笔记 `folderId`、文件夹 `parentId` 的变化随记录一起合并。
- **文件夹删除**：合并后仍指向已删除文件夹的笔记（包括最近删除中的笔记）会改为未分类；文件夹层级修复为最多两级。

### 5.4 冲突处理

同一笔记在本地与远端都被修改，且除 `updatedAt` 外内容不同：

- `updatedAt` 较新者作为主记录；时间相同则保留本地；
- 较旧记录复制为一条新笔记作为 **冲突副本**；
- 冲突副本标题为：

  ```text
  <原标题> · 冲突副本 YYYY-MM-DD HH:mm
  ```

- 冲突副本使用新 `id`，`createdAt` 与 `updatedAt` 为本次同步时间，不置顶，不进入回收站；
- 设置页显示冲突数量与前 3 个标题，全部冲突副本可在笔记列表查看。

删除与编辑冲突：

- **远端删除、本地已编辑**：保留本地编辑内容，计入冲突（`remote-deleted-local-edited`），不生成副本；
- **本地删除、远端已编辑**：采用远端编辑内容，计入冲突（`local-deleted-remote-edited`），不生成副本。

### 5.5 删除语义

- 远端删除本地笔记时使用 **软删除**：写入 `deletedAt`，进入 **最近删除**，不会物理删除；
- 最近删除的保留时间由「最近删除保留天数」设置决定（默认 30 天，`0` 表示永久保留）；
- 文件夹被删除后，其下笔记归入未分类，不会随文件夹一起丢失。

### 5.6 幂等与特殊场景

- **重复同步幂等**：当本地与远端已一致、基线也一致时，再次同步不会新增冲突或重复副本。
- **首次同步（云端无自动备份）**：远端为空，以本地数据为准上传，不下载远端内容。
- **云端自动备份全部被手动删除**：下一次同步不会把旧基线当成「远端删除了所有笔记」。此时以空基线合并，本地记录按新增处理，结果以本地为准，并重新建立基线；不会因此误删本地笔记。
- **上传失败**：同步引擎可能已写库但上传失败；此时不更新基线、上次同步时间与远端文件名，下次会重新尝试，避免把失败轮次当成成功基线。

## 6. 安全模型

### 6.1 加密算法

- 口令派生：PBKDF2-SHA-256，**310000 次**迭代；
- 内容加密：AES-GCM-256，带认证标签；
- `.tmplenc` 文件头包含魔数、版本、迭代次数、16 字节随机盐与 12 字节随机 IV；
- 手动存档与自动备份共用 `archiveCrypto.js`，不维护第二套格式。

### 6.2 云端只保存密文

上传前在浏览器本地完成加密，百度网盘中只有 `.tmplenc` 密文。没有口令无法还原笔记内容。

### 6.3 自动口令的保存方式

启用自动备份时可以选择 **在本机加密保存口令**：

- 本机生成一把 **AES-GCM-256、`extractable=false` 的设备密钥**；
- 设备密钥以 `CryptoKey` 形式保存在 IndexedDB 的 `secrets` 仓库，应用无法导出其原始字节；
- 自动同步口令用该设备密钥加密后，同样保存在 `secrets` 仓库；
- 口令与设备密钥都不会写入 `settings`、`localStorage`、`sessionStorage`、日志或 DOM。

浏览器不支持安全保存（缺少 WebCrypto、无法持久化 `CryptoKey`、无痕模式或存储不可用）时，只能选择 **仅本次会话**：口令仅保存在页面内存，每次打开应用需要手动解锁。

此外使用口令校验值做本地校验：用口令加密固定文本 `tmplnote-auto-pass-check`，把密文 Base64 存入 `baiduAuto.passphraseCheck`。校验值不含明文口令，也不参与云端文件解密。

### 6.4 手动上传口令不保存

手动「上传存档」时输入的口令只用于本次加密，不会被保存。自动模式与手动模式在口令保存上不同，请勿混淆。

### 6.5 token 与桥接层

- `access_token` 仅保存在本机 IndexedDB 设置中；
- token 不进入备份 JSON，不写入云端文件；
- 桥接层从请求头 `X-Baidu-Token` 读取 token，仅拼接到转发到百度域名的 URL，不记录、不持久化；
- 桥接层只允许转发到 `pan.baidu.com`、`pcs.baidu.com`、`d.pcs.baidu.com` 与 `*.baidupcs.com`，不透传 Cookie / Origin / Referer。

### 6.6 口令遗失

口令遗失后无法解密云端存档，也无法通过应用找回。请自行妥善保管；共享设备上不建议开启「在本机加密保存口令」。

## 7. 恢复与迁移

### 7.1 手动下载恢复（合并 / 覆盖）

1. **设置 → 网盘**，在云端存档列表选择一个 `.tmplenc` 文件。
2. 点击 **下载并恢复…**，输入该文件的口令。
3. 解密成功后选择恢复方式：
   - **合并**：保留本地已有记录；只导入备份中本地不存在的笔记/文件夹（同 `id` 不覆盖、不更新）；
   - **覆盖**：清空现有笔记与文件夹后导入备份，不可撤销。
4. 点击 **恢复**。完成后笔记与文件夹列表会刷新。

### 7.2 新设备迁移

1. 在新设备上完成百度网盘连接：同一 token、同一应用目录、同一桥接地址；
2. 启用自动备份，使用 **同一个自动同步口令**；
3. 开启 **双向同步** 并执行 **立即同步**；
4. 若希望从零开始，也可以先在云端存档列表手动下载最新自动备份并选择覆盖恢复，再开启自动同步。

注意：新设备首次同步前请确认本地没有需要保留的新数据；开启双向同步后会按合并规则处理，冲突会保存副本，但大量无关数据合并仍需要人工清理。

### 7.3 查找与处理冲突副本

- 冲突副本标题包含 ` · 冲突副本 YYYY-MM-DD HH:mm`，可在笔记列表或搜索中查找「冲突副本」；
- 设置页状态卡显示冲突数量与前 3 个标题；
- 处理方式：对比主记录与副本内容，保留需要的一版，删除或归档另一版；
- 删除冲突副本属于普通笔记删除，会进入最近删除，并按保留天数清理。

### 7.4 从最近删除恢复

- 远端删除的本地笔记会进入 **最近删除**，不会立即丢失；
- 在「最近删除」中找到对应笔记并恢复；
- 若最近删除保留天数设为 `0`，则不会自动清理。

## 8. 常见问题

### token 过期或无效怎么办？

常见提示包括「access_token 无效或已过期」「token 已失效」。重新通过百度 OAuth 获取 token，粘贴到 **设置 → 网盘**，点击 **验证并保存**。token 失效后自动任务会停止尝试；重新验证保存后，请手动点击一次 **立即备份 / 立即同步**（或暂停后重新启用）让自动调度恢复。

### 桥接地址返回 404 或返回网页怎么办？

- Cloudflare Pages 默认使用 `/api/baidu`，确认部署包含 `functions/api/baidu.js`；
- GitHub Pages 等纯静态托管没有 Pages Functions，必须自行部署 Worker，并填写完整桥接地址；
- 桥接地址应返回 JSON 或文件流，而不是 HTML 页面；
- 本地开发使用 `npm run dev`，内置 `/api/baidu`。

### 出现 `-7`「应用目录不存在或当前 token 无权限访问」怎么办？

- 确认应用目录与开放平台注册的产品名一致，且以 `/apps/` 开头；
- 确认 token 属于同一个百度账号，应用已开通上传权限；
- 确认应用目录已存在；必要时先在百度网盘中创建 `/apps/{应用名}`。

### 口令错误或解密失败怎么办？

- 自动备份使用启用时设置的 **自动同步口令**，手动存档使用上传时输入的口令，两者可能不同；
- 解密失败无法区分「口令错误」与「文件损坏」，请先确认口令；
- 若本机保存的口令无法解密，可清除已保存口令后重新输入；若口令确实遗失，云端文件无法恢复。

### 自动备份没有触发怎么办？

按顺序检查：

1. 是否已完成连接并启用自动功能；
2. 当前会话是否已解锁（尤其选择「仅本次会话」时）；
3. 是否在线、页面是否可见；
4. 访问锁是否处于锁定状态；
5. 最近 30 秒是否有键盘/指针输入；
6. 距上次自动运行是否不足 60 秒；
7. 是否处于失败退避期，或 token 已失效；
8. 数据指纹是否未变化（纯备份模式下会跳过）。

### 冲突数量很多怎么办？

同一笔记在两台设备上离线修改，或两次同步之间多处改动，容易产生多个冲突副本。合并本身不会丢数据，但需要人工整理。建议避免在多台设备上同时编辑同一篇笔记；处理后删除不需要的副本。

### 云端文件太多，如何调整保留？

在 **设置 → 网盘 → 自动同步与备份 → 保留份数** 中调整，界面预设 3 / 7 / 15 / 30，实际支持 1–100。只影响 `tmplnote-auto-*` 自动备份，不会删除手动 `tmplnote-archive-*` 存档。调整后下次自动备份或同步时按新份数清理。

### 如何关闭自动同步、清除已保存口令？

- **暂停**：在状态卡点击 **暂停**，停止后续自动运行，保留配置与已保存口令；
- **关闭双向同步**：在状态卡关闭「双向同步（多设备）」开关，自动运行恢复为仅备份；
- **清除已保存口令**：点击 **清除已保存口令**。若当前会话口令来自已保存记录，会话也会被锁定；若口令是本次输入且未保存，则保留当前会话。

### 如何彻底重置云端加密？

1. 先暂停自动功能，避免重置过程中又上传新文件；
2. 在云端存档列表中手动删除所有 `tmplnote-auto-*`（以及需要更换口令的 `tmplnote-archive-*`）；
3. 清除本机已保存的自动同步口令；
4. 重新启用自动备份，设置新口令与保留份数；
5. 下一次同步/备份会以本地为准重建云端自动备份与基线。

注意：删除云端自动备份后，下一次同步会把本地视为权威并重建基线，不会误删本地笔记；旧的手动存档若仍保留，需要旧口令才能解密。

## 9. 已知限制

- **远端状态只取最新一份自动备份**：两台设备在同一时间窗口并发上传时，可能需要下一轮同步才能收敛；合并规则不会因此删除另一台设备的本地数据。
- **不支持实时增量块同步、多人协同、附件单独同步**：每次备份/同步都是完整数据快照。
- **只同步笔记与文件夹**：AI 对话历史、模型文件、token 等不会进入同步或备份。
- **完整备份体积随数据增长**：数据量很大时，加密与上传会较慢；单个存档上传/下载上限为 50 MB。
- **冲突不自动合并正文**：同一笔记两侧修改时保留较新版本并生成副本，需要人工处理。
- **自动运行依赖浏览器状态**：页面隐藏、离线、访问锁锁定、用户正在输入或浏览器休眠时不会运行。
- **加密依赖安全上下文**：非 HTTPS 且非 `localhost` 的环境无法使用 WebCrypto。
- **口令不可找回**：遗失后云端存档无法解密。

## 10. 隐私说明

- 应用不包含遥测，不向第三方统计服务发送使用数据。
- 笔记数据只在你的设备与百度网盘之间传输；桥接层仅做请求转发。
- 桥接层不记录 token，也不持久化请求内容。
- 云端只保存口令加密后的 `.tmplenc` 密文。
- `access_token` 仅保存在本机 IndexedDB，不进入备份或云端文件。
- 自动同步口令仅在以下位置之一出现：当前页面内存，或以本机不可导出设备密钥加密后的密文（IndexedDB `secrets`）。
- 冲突副本保存在本地笔记库中，并随下一次自动备份/同步加密上传。
